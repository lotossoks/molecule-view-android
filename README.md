# molecule-view-android

Проект Android-приложения для просмотра молекулярных структур с управлением пальцами.

Статус: исследование и согласование архитектуры, 1 ноября 2026 года. Код приложения ещё не написан. Согласованы Compose + локальный Mol*, основной масштаб до 100 тысяч атомов (белки и лиганды), встроенная консоль с максимально знакомым синтаксисом PyMOL. Остальные предложения требуют проверки или согласования.

Репозиторий: https://github.com/lotossoks/molecule-view-android (создан приватным).

## Результат исследования

Выбранный вариант: Kotlin + Jetpack Compose для интерфейса и локально упакованный Mol* для 3D-сцены в Android WebView. Это нативная Android-оболочка с веб-рендерером. Альтернативы ниже сохранены как результат исследования и резерв на случай проблем прототипа.

Платформа: Android 12+; основной телефон пользователя — Honor X9e Pro под Android 16 (название со слов пользователя, характеристики и RAM не проверены). Проверять совместимость на Android 12 и работу на основном устройстве; версию Android System WebView записывать отдельно. Русский и английский интерфейс остаются предлагаемым вариантом.

Распространение: сначала личный APK и GitHub Releases в приватном репозитории. Публикация в магазинах и открытие исходников пока не запланированы. Для обновлений APK сохранять постоянные application ID и ключ подписи; ключ и пароли не хранить в Git. Выбор лицензии проекта отложен, уведомления о лицензиях зависимостей включать в сборку.

| Вариант | Основание для рассмотрения | Что проверить / цена решения |
|---|---|---|
| Mol* | Развитые выделения, окружения, структуры, поверхности, собственные представления и координатные форматы | WebView, память, точность picking, возможность покадровой загрузки |
| NGL | В документации заявлены молекулярные форматы, XTC/TRR/DCD и удалённые траектории через MDSrv | Сравнить на одинаковых данных и телефонах при проблемах Mol* |
| 3Dmol.js | API отображения, стили, поверхности и выборки; кандидат для более простого viewer | Проверить покрытие GRO и будущих траекторий перед выбором |
| Собственный OpenGL/Vulkan renderer | Полный контроль над Android-рендерингом | Потребуется реализовать или интегрировать парсеры, научные представления, выборки и анализ; большой отдельный проект |

Это инженерная рекомендация по соответствию требованиям, а не результат измерения скорости. Десктопные демонстрации больших структур нельзя считать мобильным benchmark.

Источники: [Mol*](https://github.com/molstar/molstar), [выделения](https://molstar.org/docs/v5/plugin/selections/), [NGL](https://nglviewer.org/ngldev/api/), [3Dmol.js](https://www.3dmol.org/doc/tutorial-embeddable.html).

Документация Mol* v5 и текущая ветка разработки различаются: README репозитория описывает v6 prototype с другой структурой пакетов. Перед прототипом выбрать конкретный опубликованный стабильный релиз, закрепить версию и lockfile; не строить приложение на произвольном master. Версия пока не выбрана.

## Пользовательские сценарии и границы первого релиза

1. Открыть файл через системный picker или «Открыть с помощью», увидеть структуру и базовую информацию. Повторно открыть недавнюю структуру офлайн.
2. Ввести PDB ID, скачать структуру с прогрессом и отменой, выбрать biological assembly или asymmetric unit. Не ограничивать модель идентификатора четырьмя символами: RCSB документирует расширенные ID.
3. Переключать cartoon, sticks, ball-and-stick, spacefill, surface; применять стиль ко всей структуре или именованному выделению. Цвета: элемент, цепь, вторичная структура; дополнительные свойства — только если присутствуют в данных.
4. Выбрать цепь, остаток, лиганд, атом или диапазон остатков. Найти объект по имени/номеру в списке либо последовательности. Добавлять к выделению, исключать, инвертировать, сохранять именованные выборки.
5. Открыть окружение лиганда/фрагмента: радиус в Å, атомы либо целые остатки, включение/исключение исходного выделения, воды и ионов. Сфокусировать камеру, скрыть остальное или сделать контекст прозрачным.
6. Измерить расстояние между двумя явно выбранными атомами. Для пары остатков уточнять метрику, не выдавать произвольную дистанцию за единственно правильную.
7. Сохранить сессию и изображение, поделиться изображением через Android. Повторить операции из встроенной консоли.

Из ChimeraX полезно перенести связку «выделение → зона → стиль → измерение», не весь набор меню. Контакты и водородные связи добавить после минимального релиза: геометрическая близость сама по себе не доказывает наличие химического взаимодействия. [Учебный материал разработчиков ChimeraX](https://rbvi.github.io/chimera-tutorials/presentations/modules/chimerax-comp-structures/index.html).

После первого релиза: сравнение/совмещение структур, карты плотности, углы и диэдралы, аннотации, MD и удалённые источники. Редактирование молекул, docking, минимизация и полноценный Python runtime не входят в исходный объём.

## Мобильный интерфейс

Цель макета: при закрытых панелях сцена занимает около 85% доступной площади. Небольшая верхняя строка с названием и загрузкой, нижние действия «Открыть», «Стиль», «Выделение», «Ещё». Консоль доступна из «Ещё» и может быть закреплена пользователем.

- Один палец вращает; pinch масштабирует; перенос двумя пальцами с согласованным распознаванием жестов.
- Короткое касание выбирает объект и показывает компактную карточку. Явный уровень выбора: остаток по умолчанию, атом/цепь/молекула по запросу.
- Не зависеть от hover, правой кнопки или клавиатурных модификаторов. Не использовать незаметный долгий тап как единственный путь к функции.
- Если рядом несколько объектов, показывать список кандидатов. Для точного атома — поиск по имени и увеличение сцены.
- Панели снизу: свернутая карточка, промежуточная высота, полный список по необходимости. Только одна рабочая панель одновременно; Android Back закрывает её.
- Переключатели воды/ионов, «Фокус», «Окружение», «Скрыть остальное», «Отменить» доступны из карточки выделения.
- Последовательность показывается по запросу с поиском остатка и вводом диапазона; постоянно сверху сцену не занимает.
- Альбомная ориентация, системные отступы, крупный шрифт, TalkBack для списков и действий. Проектная цель — интерактивные зоны не меньше 48 dp.

Стандартные панели Mol* в приложение целиком не переносить. Нужна минимальная конфигурация движка с собственным Android UI. [Создание экземпляра Mol*](https://molstar.org/docs/v5/plugin/instance/), [исходная модель управления viewer](https://molstar.org/viewer-docs/).

## Форматы

Ниже — план поддержки приложения, а не уже реализованные возможности.

| Этап | Форматы | Особенности |
|---|---|---|
| v1, обязательные | PDB/ENT, PDBx/mmCIF, MOL2, GRO | Проверка реальными образцами, нескольких моделей, единиц и идентификаторов |
| v1, дополнения | BinaryCIF, SDF/MOL, XYZ | SDF может содержать несколько соединений; XYZ не гарантирует наличие связей |
| После базового импорта | PDBQT, coreCIF, gzip-обёртки | Отдельно проверить docking-метаданные, кристаллические структуры и предел распаковки |
| MD | GRO/PDB + XTC, затем TRR/DCD; TOP/PSF/PRMTOP по необходимости | Координатам нужна совместимая структура/топология |
| Позднее | MRC/CCP4/MAP, CUBE, DX | Объёмные данные, отдельные органы управления |

Парсеры этих групп перечислены в [документации Mol*](https://molstar.org/docs/v5/plugin/file-formats/). Поддержка парсера не означает, что все расширения формата, метаданные и сценарии уже проверены.

CIF определять по содержимому/схеме: mmCIF и coreCIF нельзя считать одним случаем. Для GRO явно проверять преобразование nm → Å и восстановление связей; GRO не считать полной силовой топологией. Догаданные связи отличать от заданных в файле. Для multi-model PDB отделять набор моделей от физической MD-траектории.

Загрузка по PDB ID: предпочтительно BinaryCIF с fallback на mmCIF; сохранять исходный идентификатор, источник, assembly и checksum. [RCSB File Download Services](https://www.rcsb.org/docs/programmatic-access/file-download-services).

## Предлагаемые архитектурные границы

Поток управления: Compose UI / консоль → типизированные команды → сессия приложения → адаптер Mol* → сцена. События выбора и прогресс идут обратно через тот же версионированный протокол.

- `app`: Android lifecycle, Compose, системное открытие файлов, навигация.
- `session`: источники, документы, объекты сцены, выборки, стили, камера, история и сериализация с миграциями.
- `commands`: парсер пользовательского синтаксиса, AST, проверка аргументов, выполнение команд из UI и консоли.
- `engine`: узкий контракт загрузки, selection, representation, camera, measurement, frame, export; реализация Mol* в локальном TypeScript bundle.
- `data`: единый доступ к байтам для локального документа, HTTPS/PDB, будущего SFTP; возможности источника описаны явно (`seek`, длина, стабильная версия).
- `trajectory`: отдельные TopologySource, FrameSource, индекс кадров и ограниченный кеш; пока контракт и план, без проигрывателя v1.

Это логические границы: не обязательно создавать отдельный Gradle-модуль для каждой сущности сразу. Не копировать полный атомный граф в Kotlin и JavaScript одновременно. Движок владеет научными данными, Kotlin — пользовательской сессией, источниками и идентификаторами команд.

Mol* упаковывается в APK, без CDN; локальное открытие работает в авиарежиме. WebView загружает ресурсы через WebViewAssetLoader. Нативный слой обрабатывает файловые URI и скачивание; в bridge передаются небольшие типизированные сообщения, не огромные base64-строки. Конкретный бинарный транспорт выбрать по измерениям прототипа. [Android: локальное содержимое WebView](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content).

Bridge: версия протокола, request ID, завершение/ошибка, отмена, readiness, события изменения сессии. Только доверенный локальный origin; никаких произвольных JS-команд из консоли. После поворота экрана или потери процесса восстанавливать сессию, а не ссылку на старые объекты JS.

Стабильная идентичность выбора должна включать источник/модель, chain auth/label IDs, residue ID и insertion code, atom name/altloc и assembly instance. Нельзя сохранять только индекс атома или номер остатка. Для форматов без этих полей использовать документированный локальный идентификатор. Состояние приложения версионировать независимо от внутренних snapshot Mol*.

## Командная строка

Согласованный ориентир: встроенная консоль с максимально знакомым синтаксисом PyMOL, автодополнением и историей. Реализовать документированное подмножество команд и selection algebra; MolScript использовать внутри адаптера. MolScript/MolQL — язык запросов, а не готовая полная консоль PyMOL. Полную совместимость, Python API, плагины и запуск произвольных существующих .pml без проверки не обещать.

Эскиз синтаксиса для обсуждения, пока не исполняемый:

```text
fetch 1crn
select active, chain A and resi 10-25
select pocket, byres (active around 5)
show sticks, pocket
color yellow, pocket
hide everything, solvent
zoom pocket
distance d1, atom1, atom2
```

Нужно определить приоритет логических операторов, quoting, единицы, пространства auth/label, область поиска окружения и статические/динамические выборки. Для знакомых операторов сохранять семантику PyMOL, в особенности around, within и byres; подтвердить эталонными тестами. atom1/atom2 в примере — предварительно созданные одноатомные выборки. Покрытие команд и отличия документировать отдельно; неизвестный синтаксис не интерпретировать приблизительно. Все жесты и кнопки вызывают те же команды, что консоль; операции можно воспроизвести. Сценарий хранит версию языка и ссылки/хеши входных данных. Неизвестная команда показывает ошибку до изменения сцены.

Встроенная консоль и внешняя CLI — разные функции. Termux/ADB, интенты и пакетная автоматизация требуют отдельного решения о входных данных и правах. Открытие командного файла не должно автоматически запускать сетевые действия.

## Задел под MD и SFTP

MD: хранить топологию отдельно от кадров. FrameSource возвращает координаты, время, box и единицы; renderer обновляет координаты без пересоздания всей структуры. Проверять число и порядок атомов; совпадение количества само по себе не подтверждает правильное соответствие.

XTC: запланировать индекс смещений, отменяемое индексирование, prefetch и ограниченный LRU-кеш; не загружать всю траекторию в память. Для источника без seek сначала предложить локальный кеш с проверкой места. Выбор декодера JS/WASM/native зависит от проверки возможности извлекать отдельные кадры и стоимости копирования данных. [Mol*: расширение загрузки траекторий](https://molstar.org/docs/v5/plugin/transforms/custom-trajectory/).

Оценка только координат: 100 000 атомов × 3 × 4 байта ≈ 1,2 MB на кадр; тысяча кадров ≈ 1,2 GB без топологии, GPU и временных копий. Поэтому полноценная MD-поддержка не сводится к добавлению кнопки Play.

Отдельно запланировать PBC/wrapping/centering, необязательное выравнивание, выбор stride, статические и пересчитываемые на каждом кадре окружения. Для последнего нужны лимит частоты и отмена устаревших вычислений.

SFTP выполняется Android-слоем, не WebView. Сначала просмотр каталогов и загрузка в кеш, затем чтение диапазонов для индексированных траекторий. Возобновление проверяет, что удалённый файл не изменился. Ключи/пароли не входят в сессию или сценарии; проверка host key обязательна.

ProxyJump через промежуточный сервер — обязательное требование первого этапа SFTP после v1. Контракт подключения сразу описывает конечный сервер и упорядоченный маршрут переходов, с отдельными параметрами аутентификации и host key для каждого узла. Минимальный сценарий приёмки: один bastion и целевой SFTP-сервер; несколько переходов — задел модели, не обещание первого выпуска. Отмена и разрыв соединения закрывают всю цепочку; повторное соединение заново проверяет её и актуальность удалённого файла.

Импорт ssh-config: Host, HostName, User, Port, IdentityFile и ProxyJump входят в исходный объём удалённого доступа; ограниченный Include — следующий этап. Выбирать SSH-библиотеку с подтверждённой поддержкой туннелирования до целевого SSH-соединения и SFTP через него. Desktop-пути к ключам нужно сопоставлять с выбранными на Android файлами. Неподдержанные директивы показывать явно. Произвольные ProxyCommand и Match exec не выполнять. Полную совместимость с OpenSSH не обещать. Семантика первого применимого значения и Host patterns должна быть сохранена. [OpenSSH ssh_config](https://man.openbsd.org/ssh_config).

## Этапы и критерии готовности

1. Основные решения согласованы: Compose/Mol*, до 100 тысяч атомов, консоль в стиле PyMOL, Android 12+, приватные APK/Releases, будущий ProxyJump. Лицензия и детали локализации пока открыты и не блокируют технический прототип.
2. После согласования сделать технический прототип: локальный Mol* без desktop UI, загрузка через Android picker, touch selection и окружение, измерение памяти и кадра. Зафиксировать версии движка и WebView.
3. Прогнать малую молекулу, белок с лигандом, систему порядка 100 тысяч атомов и стресс-пример порядка миллиона. Это диапазон исследования, не обещание поддержки. На согласованном устройстве предложенная цель — не менее 30 FPS при вращении обычной структуры; предел памяти и допустимое время загрузки определить после замеров.
4. Проверить риски будущего FrameSource коротким экспериментом с парой GRO/XTC: доступ к выбранному кадру без удержания всех кадров. Проигрыватель пользователю пока не выпускать.
5. Собрать v1: импорт, PDB, стили, выделения/окружения, расстояние, консоль, сохранение сессии/изображения.
6. Проверить каждый заявленный формат на валидном и повреждённом файле, отмену, отсутствие сети, отсутствие места, восстановление сессии, rotation/background, смену стиля и несколько одновременно открытых структур.
7. Для научной корректности сравнить результаты окружений и расстояний с эталонами; отдельные случаи: insertion codes, altloc, author/label IDs, assembly copies, пустые выборки, GRO units. Один и тот же запрос из UI и CLI должен давать одну выборку.
8. После v1: MD, SFTP, расширенный анализ. Если Mol* не проходит согласованные критерии, провести ограниченное сравнение NGL до разработки основного интерфейса.
